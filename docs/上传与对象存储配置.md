# 本机图片上传与对象存储配置

## 为什么需要对象存储

智能体平台部署在另一台机器上，它的视觉节点只能读取**公网可访问的图片直链**。因此：

- 本机地址（`http://127.0.0.1:8789/...`）平台读不到，会在调用平台之前就被拒绝（`image.rejected`）。
- 临时图床（uguu.se、catbox 等）直链几小时到几天就过期，过期后平台读图失败。本项目已经踩过这个坑，现在服务启动时会直接拒绝这类链接。

所以上传的图片必须落到我们自己可控、长期有效的对象存储里，再把返回的直链交给平台。

## 数据流

```
浏览器选择 JPG/PNG
  → POST /api/upload（原始二进制 + Content-Type: image/jpeg|image/png）
  → 后端校验：类型白名单 → 大小上限 → 文件头嗅探 → 声明类型与实际内容一致
  → 生成对象名 <前缀>/YYYY/MM/DD/<uuid>.<jpg|png>
  → 存储 driver 写入对象存储
  → 返回公网直链
  → 网页填入“公网图片链接”
  → 复用原有 /api/mission 调用平台
```

密钥只在后端环境变量里，页面拿到的只有最终 URL。

## 校验规则

| 规则 | 失败时的 stage | HTTP |
| --- | --- | --- |
| 只允许 `image/jpeg`、`image/png` | `upload.unsupported_type` | 415 |
| 内容不能为空 | `upload.empty` | 400 |
| 不超过 `UPLOAD_MAX_BYTES`（默认 8 MiB），超限立即中断接收 | `upload.too_large` | 413 |
| 文件头必须是真的 JPG/PNG | `upload.not_an_image` | 400 |
| 声明的类型必须与实际内容一致 | `upload.type_mismatch` | 400 |
| 对象存储必须已配置 | `upload.storage_unconfigured` | 503 |
| 写入对象存储失败 | `upload.storage_failed` | 502 |

对象名用日期分层加 UUID，同名文件不会互相覆盖。

## 配置

在**不提交**的 `.env.local` 里填写（`.env.example` 只有变量名和说明）：

```
STORAGE_DRIVER=aliyun-oss
OSS_REGION=<例如 cn-hangzhou>
OSS_BUCKET=<你的 bucket 名>
OSS_ACCESS_KEY_ID=<AccessKey ID>
OSS_ACCESS_KEY_SECRET=<AccessKey Secret>
# 可选
OSS_PREFIX=flood-demo
UPLOAD_MAX_BYTES=8388608
```

安全要求：

- AccessKey 只放后端环境变量，绝不写进 HTML、前端 JS，也绝不提交 Git（`.env.local` 已在 `.gitignore`）。
- 建议使用只对该 bucket 有写入权限的子账号 AccessKey，而不是主账号密钥。
- 上传的对象需要能被平台匿名读取，平台才能取图。

服务启动时会打印当前 driver 与是否可用；未配置时上传接口返回 503，并列出缺少的**变量名**（不会输出任何取值）。网页上的上传按钮此时是禁用状态，并显示原因。

## 本地联调（不需要真实 OSS）

```
STORAGE_DRIVER=local
DEMO_ALLOW_LOCAL_IMAGE_URLS=1
```

这样可以完整走通「选图 → 上传 → 得到 URL → 发起巡检研判」的链路，但图片只存在本机，只能配合本地假网关或本机可被平台访问的隧道使用。生产演示不要用这个组合。
