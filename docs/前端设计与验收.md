# 汛巡智眼前端设计基线

## 视觉方向

定位为深色 GIS 智能巡检工作台。采用深海蓝背景、青绿色操作与流程状态、细线分区；红、橙、绿分别表达高、中、低风险。待核验使用灰色和文字标识，不依赖颜色传递结论。中间大图保留完整画幅，右侧风险等级环只表达实际返回等级，不计算虚构风险指数。

品牌标识采用透镜与观测点的几何组合。沿用系统中文字体，不依赖在线字体、地图 SDK 或动画资源；断网仍可展示本地预置素材。

## 布局

- 宽屏：固定侧栏、顶部区域示意横幅；主区采用任务信息、大型巡检影像、风险与区域说明三栏；流程时间线与人工处置位于主区下方。
- 1280px：导航收为图标栏；中等宽度继续缩小时，影像与研判自然换行。
- 手机：顶部紧凑导航，任务、影像、风险、时间线、处置依次排列；表单字号至少 16px，所有操作可滚动访问。
- 任务配置和任务详情通过标签切换，完成研判后自动显示详情；修改输入仍走原有失效清理逻辑。
- 六张缩略图由原素材选择器派生，选择触发同一 change 事件。原图对话框支持关闭按钮和 Escape。
- 地图由本地原创 `online-experience/region-map.svg` 绘制，明确标注区域示意、非实时、无定位数据；位置卡仅展示当前事件的文字位置。
- 流程不根据计时器推测真实节点进度；真实网关未返回分阶段状态时统一等待结果，收到结构化研判后才完成前三阶段。

## 维护入口

- `online-experience/ui.css`：颜色、字体、布局、响应式和所有展示组件。
- `online-experience/ui.js`：侧栏、任务标签、影像查看、缩略图、区域说明与显式 UI 状态更新边界。
- `online-experience/workspace.js`：研判展示、复核与工单标签、审批锁定和任务生命周期约束。

在线体验与真实调用复用这些文件。视觉改动不应复制两套不同的交互逻辑。

## 每次改版必须核验的边界

1. 同一工单只能有一个当前最终决定。审批后按钮和审批意见锁定，撤销后才可重新审批。
2. 并发重复审批请求只追加一次后端记录，旧决定不能撤销已经改变的决定。
3. 同一任务已有工单后不能重复生成。修改任务、图片链接或素材后清理旧结果、旧工单和旧审批意见。
4. 操作过程中不能切换任务输入。全局按钮解锁不能解锁已完成的审批。
5. 空复核意见有明确提示。真实复核没有返回新的结构化研判时，不允许用旧研判生成工单。
6. 无事件、待核验、失败和影像不可用都应有可读状态，不能伪造事件、进度、定位框、地图或统计数字。
7. 检查桌面、中等宽度和手机的溢出、键盘焦点、标签切换与图片放大。
8. 观测标识只在巡检研判请求处理中扫描。完成和失败必须停止；工单与审批不能触发扫描。切换输入恢复待开始状态，失败可重试；减少动态效果时显示静态标识，不虚构检测点或进度。
9. 风险卡片与影像下方证据区共用当前研判事件。选择只改变展示，不修改研判或审批数据；没有坐标时仅展示文字位置，不绘制定位框。新任务、素材切换和结构化复核更新清除旧选择；无风险事件时隐藏证据区。按钮可通过键盘操作，窄屏选择后将证据带入视野，减少动态效果时取消平滑滚动。
10. 风险卡片作为摘要列表，证据原文最多显示两行；完整视觉依据、处置建议和模型置信度集中在联动证据区。摘要不改写模型结论，原始输出仍可展开查看，不能因精简展示而删除任务数据。

自动化检查运行 `npm test`。真实平台连通与调用输出需在配置好密钥的校园网环境另外验收；预置体验不能替代真实验证。

## 浏览器验收

可选脚本 `tests/browser-acceptance.mjs` 使用外部安装的 `playwright-core` 和本机 Edge，不为运行页面引入依赖。设置 `PLAYWRIGHT_MODULE` 为该包路径后运行 `node tests/browser-acceptance.mjs`；服务地址由 `UI_TEST_URL` 指定，默认 `http://127.0.0.1:8789`。截图输出目录通过 `UI_SCREENSHOT_DIR` 设置。

覆盖 1920×1080、1440×900、1280×800、390×844，风险／无风险／待核验、证据关联、空复核校验、修改、取消、工单防重复、三种审批与撤销、输入失效清理、上传预览和错误状态。真实入口的浏览器请求使用明确的本地响应夹具，不调用真实平台。

体验版自有上传图片只供预览，不对其套用已有案例的研判。无法解析的真实返回显示错误并禁止生成工单，原始内容保留在错误反馈中。上传期间锁定任务输入，成功更换直链后清理旧结果。
