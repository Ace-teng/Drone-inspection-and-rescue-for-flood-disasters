# 视觉定位接入核查

核查日期：2026-10-09。

## 已确认的事实

- 本项目调用校园网 OpenTrek 智能体网关，提交任务文字与图片附件；本地没有直接设置视觉模型名称。
- `real-demo-server.mjs` 的 `mission()` 调用已发布巡检智能体，`lib/agent-gateway.mjs` 的 `run()` 读取最终文本输出。视觉节点配置与节点间数据转换没有导出到本仓库。
- 在线体验的事件只有风险类型、等级、文字位置、置信度、视觉依据和建议，没有定位坐标。它们是预置案例，不能用来证明真实模型的定位能力。
- 百炼官方文档说明视觉模型可进行物体定位。Qwen2.5-VL 输出相对于缩放后图像的像素坐标；Qwen3-VL 输出归一化坐标，范围为 0–999。因此不能看到四个数字就默认按原图像素画框。来源：[阿里云视觉理解文档](https://help.aliyun.com/zh/model-studio/vision/)。

## 尚待平台确认

1. 视觉节点实际使用的模型完整名称与版本。
2. 是否缩放、裁剪或旋转输入影像，定位参考画幅如何确定。
3. 当前视觉节点的提示词与输出结构，是否能稳定返回二维边界框。
4. 风险研判、人工复核与最终输出节点是否保留定位字段和事件关联。
5. 当前代码固定调用的已发布版本是否包含上述配置；修改工作流后需核对新发布版本。

平台根入口本次未能在浏览器中加载；已配置路径 `/sfm-agent-studio/` 的 HTTP 检查返回 404，不能据此判断模型不支持定位。需要准确的工作流编辑页面入口或导出配置。

## 建议的输出约定（待确认模型后落实）

在每个事件内新增可选 `localization`，不替换现有文字 `location`。所有现有研判字段继续保留。

- `bbox`：四个数，顺序明确为 `[x_min, y_min, x_max, y_max]`。
- `coordinate_space`：明确为 `normalized_999` 或 `pixels`，不由前端猜测。
- 像素坐标需附 `reference_width`、`reference_height`，由预处理或平台元数据提供，不让语言模型猜图片尺寸。
- `source`：明确为 `model`；无法可靠定位时 `localization` 为 `null`。
- 一条事件有多个目标时需明确扩展为框列表，不能把多个框混成四个数。

参考：无法定位时该事件增加 `"localization": null`。本说明不提供任何虚构框坐标。

## 接入与验收

先用项目测试影像检查视觉节点的真实原始返回，再检查最终研判 JSON 是否保留同一框及事件关联。两处都确认后才启用前端叠加。

前端应验证数值、顺序与范围，拒绝无尺寸来源的像素框；按图片实际显示画幅计算位置，考虑 `object-fit: contain` 的留白。正常结果、无坐标、无效坐标保持文字证据展示。

验收包含卡片和框双向选择、缩放与窄屏对齐、切换素材清空、人工复核后的定位更新、工单与审批回归。模型定位仍需人工核验，不能把模型预测标为已核实位置。
